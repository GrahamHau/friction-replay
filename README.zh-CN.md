# friction-replay

[English](./README.md)

**用户卡住了才上传**的操作回放。

页面用 [rrweb](https://github.com/rrweb-io/rrweb) 录进浏览器内存里的环形缓冲（约 5 分钟），平时一字不传；
一旦判出卡点，上传「事发前几分钟 + 事发后 2 分钟」作为一段回放。思路同 Sentry 的「出错才上传」，
但可自托管、不依赖框架、体积小。

| 卡点 | 判定 |
| --- | --- |
| `rage_click` 连续狂点 | 同一元素 1 秒内点 3 下 |
| `dead_click` 点了没反应 | 点按钮 / 链接后 1.5 秒内页面没变化、没有请求结束、没跳转 |
| `error` 报错 | 未捕获异常、同源请求 4xx/5xx 或网络失败、页面上标了 `data-replay-error` 的错误提示 |
| `form_abandon` 填到一半放弃 | 表单 / 弹窗里输入过内容，没提交就被关掉或离开了页面 |
| `manual` 手动 | 调 `recorder.capture()`，比如用户提交反馈时 |

## 特点

- **默认保护隐私**：输入框一律打码；`[data-replay-block]` 区域整块不录；没遇到问题的用户不上传任何画面。
- **省资源**：rrweb 按需加载；30 秒无操作、页面隐藏时暂停录制；单次快照超过 250ms 本页停止录制，绝不拖慢页面。
- **回放一定放得出来**：缓冲按全量快照分段，事发前片段总以全量快照开头；跨源 / 沙箱 iframe 的画面可并进同一段回放。
- **报错上下文安全**：请求失败只记方法、路径（不含查询参数）、状态码、请求编号和 `{ error: { code, message } }` 信封，网址、令牌、密码、JWT 一律脱敏。

用法、服务端、播放器与演示见 [英文 README](./README.md)，接口一致。

## 本地演示

```bash
npm install
npm run demo        # 打开 http://localhost:5173
```
